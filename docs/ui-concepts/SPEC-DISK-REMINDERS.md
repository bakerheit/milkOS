# milkOS app specs: Disk Utility and Reminders

Generated by `disk-reminders.mjs` (contrast numbers computed from the tokens). Mockups: `disk-reminders.html`. Written for **the app engineer** (the apps) and **the window-system engineer** (anything touching notifications or the window API). Read `SPEC.md`, `SPEC-APPS.md` (Conventions for every app) and `ART.md` first. Only what exists today is assumed; what is missing is listed under "Needs".

## 1. Disk Utility
**Purpose:** see the disk, keep it safe, and undo mistakes: usage, Time Machine snapshots and their differences, clones, scrub and checks, encryption, and backups to the Mac. **Everything comes from `/sys/fs/milkfs/*` and the `snap` tool (docs/filesystem.md); no kernel changes are needed.**
**Window:** 900 x 640 default, 680 x 480 minimum. **Sidebar** 188 wide (oat): **VOLUMES**, one row per mounted disk: the primary volume "Milk" (selected by default), its clones ("Milk-<name>", lavender folder icon), the Mac shared folder (read-only note), and the in-memory root. Each row is 50 high: a 32px icon, the name in bold, a one-line kind in secondary text. A locked encrypted volume shows a lock glyph and "locked". **Toolbar** 44 under the title bar with the segmented control **Overview, Snapshots, Clones, Health, Security** and one primary button at the right that depends on the tab: Take snapshot (Overview, Snapshots), New clone... (Clones), Scrub now (Health), none (Security). Cmd-1 to Cmd-5 switch.

### Where each thing comes from
| In the window | Source |
|---|---|
| Size, used, free, snapshot and clone counts, format version | /sys/fs/milkfs/info |
| Snapshot list (name, time, clones) | /sys/fs/milkfs/snapshots, clones |
| Time Machine: on/off, interval, keep, daily, "next in 12m" | /sys/fs/milkfs/auto (write `on`, `off`, `interval=15m`, `keep=K`, `daily=D`, `now`) |
| Take snapshot | write a name to /sys/fs/milkfs/snapshot (or `snap create NAME`) |
| Diff | write `A [B]` to /sys/fs/milkfs/diff and read it back (`snap diff A [B|live]`): lines starting A, D, M, R |
| Roll back, Delete | write the name to /sys/fs/milkfs/rollback, /sys/fs/milkfs/delete |
| Clone, Keep (promote), Discard | /sys/fs/milkfs/clone (`SNAP NAME`), promote, discard |
| Scrub: status, start, stop, speed, schedule | /sys/fs/milkfs/scrub (read: status; write `start`, `stop`, `rate=MB/s`, `auto=off|on|7d|12h`) |
| Check, Repair | /sys/fs/milkfs/check (write `check` or `repair`, read the report) |
| Unlock, Change passphrase | write `[dev=NAME ]SECRET` to /sys/fs/milkfs/unlock; write `OLD\nNEW` to /sys/fs/milkfs/passwd (wrong secret: EACCES) |
| Back up (send), Restore (receive) | `snap send SNAP [--from OLDER] -o FILE`, `snap receive FILE [--to PATH] [--force]` |
| Volume size and usage of the other volumes | statfs (not available for non-milkfs volumes yet: show only name and kind) |
Refresh every 2 seconds while the window is visible, every 1 second while a scrub or send is running, paused when the window is hidden.

### Overview
Name at 2x, one line of facts in secondary text ("milkfs, 8.0 GB, encrypted and unlocked"), a usage bar (24 high, radius 12, honey fill on oat), "1.2 GB used   6.8 GB free", four fact cards (Snapshots, Clones, Format, Last scrub; 64 high, cream, radius 12). Then a **Time Machine card** (cream, radius 14): "On   every 15 minutes   keeps the last 8 and one a day for 14 days", "Next snapshot in 12 minutes", buttons **Snapshot now** and **Settings** (a sheet: on/off switch, interval 1 min to 2 h, keep, daily; changes persist in the superblock). And a **health card**: matcha at 13% with a matcha border and "No problems found" when the last scrub was clean (Danger-styled when it found errors, listing the files). A **records meter** appears when 24 or more of the 30 snapshot and clone records are used ("26 of 30; the oldest automatic snapshot makes room; manual snapshots are never deleted"). If an encrypted volume is not protected from backups, a one-line reminder: "Backups made with Send are not encrypted".

### Snapshots
A table: Name, Created, Kind, Clones. Header 28, rows 30, selected row straw at 20%. **Kind** is derived from the name: `auto-...` is Auto (made by Time Machine), `before-...` is "Before install" (the safety snapshot made when a clone was kept), everything else is Manual. Actions in a 44 high bar under the table: **Diff** (primary, compares with live; a menu offers another snapshot), **Clone...**, **Roll back...**, **Send...**, **Delete...** (right-aligned). Delete is disabled for a snapshot that has a clone, with the reason "This snapshot has a clone; discard the clone first" (EBUSY). **Diff view** under the bar: a heading "before-fortune compared with the live volume: 5 changes" and a list with a 26px chip per change: **A** added (matcha), **M** changed (honey), **D** deleted (Danger), **R** moved (blue), then the path. Return opens the changed file's folder in Files. Only changed parts of the disk are read, so Diff is quick. **Restore from file...** (in the toolbar's menu) opens the receive sheet (see Back up).

### Clones
A card per clone (cream, radius 14): lavender icon, name, "from the snapshot before-fortune, made Today 13:02", "Opens as /Volumes/Milk-fortune, uses 2 MB of its own". Buttons **Open in Files**, **Keep...** (primary), **Discard...**. New clone... asks for a snapshot (default the newest) and a name. Explanatory text: Keep makes the clone live and keeps the current state as the snapshot before-<name>; Discard frees what the clone wrote; neither can be undone.

### Health
**Scrub card:** state (idle, running), a progress bar (14 high, straw), "42%   2.4 GB read of 5.7 GB   about 1 minute left   32 MB/s", **Stop** (Danger pill) while running, and **Speed** chips (16, 32, 64 MB/s; default 32). **Schedule card:** "Scrub automatically every" with chips 12 h, 7 days (default), Off, and "Last full scrub: Sunday 03:12, no problems found." Errors found by a scrub are listed with the damaged file's path, the offset and every snapshot or clone that holds the block, in Danger text, with the advice to restore the file from an older snapshot (Versions). **Structure check card:** **Check** (changes nothing) and **Repair...** (asks first); the report appears in a monospace pane.

### Security
- **Encryption status card:** "Encrypted and unlocked" (matcha 13% fill) or "Not encrypted" (oat), a plain sentence ("Every block is encrypted with a key that only your passphrase or the recovery key can open"), buttons **Change passphrase...** and **Lock now**. **Lock now is drawn disabled** with "needs a lock call (not available yet)": the system can unlock but has no call to lock again.
- **Unlock sheet** (shown for a locked volume, 500 x 316): icon, "Milk is encrypted and locked", a passphrase field (dots), a link "Lost it? Use the recovery key instead" (the field then accepts the 8 groups of 4), "Three wrong tries and you wait a moment", buttons Cancel and **Unlock** (primary). A wrong secret says "That was not the passphrase" (never the system errno).
- **Change passphrase sheet:** current passphrase (or recovery key), new passphrase twice; no strength meter, just "At least 8 characters". It rewraps the key; no data is rewritten.
- **Recovery key card:** says it was shown once when the disk was made (as 8 groups of 4 digits) and can not be shown again.
- **Creating or erasing a volume is not offered** (mkfs never runs from the GUI in this version; the kernel refuses to format the mounted volume anyway). Encryption is set up when the disk is made on the Mac.
- **Backups warning card** (honey 13%, honey border): "Backups are not encrypted. A backup made with Send is a plain copy of your files. Keep it on an encrypted disk, or receive it into another encrypted volume." **Back up...** button.

### Back up and restore
**Back up sheet** (560 x 420): **Snapshot** picker, optional **Only what changed since** picker (incremental from an older one), **Save to** (default /Volumes/Mac/backups/<name>.stream, Choose... opens the Save panel), the honey warning panel "This backup is not encrypted. Anyone who gets the file can read everything in it." and a required checkbox "I understand" (Send stays disabled until ticked). Send shows a progress bar and the result; the shared folder is read-only unless the VM was started with `MILK_SHARE_RW=1`, in which case Send is disabled with "The Mac folder is read-only. Start milkOS with MILK_SHARE_RW=1 to back up to the Mac." **Restore from file...:** Open panel for a stream, target volume, a **Replace existing** switch (force, with the Danger confirm below), then Receive.

### The confirm sheet (every destructive action)
Roll back, Delete snapshot, Discard clone, Keep clone, Repair, Replace on receive, Forget (if added later). Sheet 560 wide, radius 14, window shadow, over a veil of ink at 28%. **Header 44 in Danger #B5473B** with the title as a question in #FFFDF8 ("Roll back to before-fortune?", 5.26:1). Body: one sentence of consequence in plain words with numbers ("5 changes since then, 2 added, 1 changed, 1 deleted, 1 moved, will be undone"), one sentence of what happens to the current state, and, where it is true, a checkbox **"Take a snapshot of the volume as it is now first"**, ticked by default (Keep clone, Repair). **Roll back and Replace have no such box:** a rollback deletes every newer snapshot (like zfs rollback -r), so a safety snapshot made first would be deleted with them. Their sheet instead states how many newer snapshots will be deleted and tells you to use Send first to keep a copy. A honey note appears when open files could be affected. Buttons right-aligned: **Cancel** (secondary, **the default**; Return and Esc cancel) and the verb button (**Danger** kind, named for the action: Roll back, Delete snapshot, Discard clone, Keep clone, Repair, Replace). The destructive button is never the default.

### Privilege and errors
Writing to /sys/fs/milkfs/* needs privilege. When the app runs as the ordinary user, the first destructive action asks for the user's password in a system panel (same look as the Open panel) and the app then acts through that authorisation for 5 minutes. Errors show the reason in words ("This snapshot has a clone", "Not enough room", "The volume is busy; close apps that use it") above the raw system message, which is available under Details.

### Contrast
Danger header text #FFFDF8 on #B5473B: 5.26:1. Diff chips: text ink on the change colour at 27% over the surface: A 10.85:1, M 11.06:1, R 9.94:1, D (Danger tint) 8.73:1. Danger text on milk (overdue, errors): 5.26:1; in the dark theme use #F0A0A0 (7.31:1).

### Needs
- **App engineer:** the app, the confirm-sheet pattern (reusable), a diff list, polling of the sysfs files.
- **Processes / security engineer:** a privilege model for writes to /sys/fs/milkfs (ask for the user's password once, then a short authorisation); a **lock** call (the volume can be unlocked but not locked again).
- **Window-system engineer:** none beyond sheets, which already exist.
- **Not provided:** formatting a disk, per-volume usage for non-milkfs volumes, encryption setup.

## 2. Reminders
**Purpose:** remember small things. Lists, due dates, repeats, and a gentle ring when they are due, rung by the existing alarm daemon.
**Window:** 780 x 620 default, 560 x 400 minimum. **Sidebar** 188 wide (oat): a search field (24 high), the smart lists **Today**, **Scheduled** and **All** with counts (rows 26 high, selected straw at 20%), then **LISTS**: each user list with a coloured dot and a count, and an **Add list** button (secondary pill) at the bottom. Lists take any accent colour. Default lists: Personal (straw), Home (matcha), Work (blue).
- **List view:** the list name at 2x, a line of counts in secondary text ("3 reminders, 1 overdue"), a **quick-add field** (32 high, radius 16, cream, 2px straw border while focused), then the rows. **Completed** is a collapsible group at the bottom (collapsed by default after 7 days of items; the Hide link toggles it).
- **Row:** a 22px checkbox circle with a 2px border in the list's **ink colour** (blue #4B63A8, straw #C9566B, matcha #5B8A5E, honey #A87812: non-text contrast 5.66:1, 4.11:1, 3.94:1, 3.85:1 on milk, all at least 3:1; the plain accents are too pale), the title (primary text), under it the due line in secondary text, and on the right the list name in secondary text (shown in Today, Scheduled and All). A completed row has the circle filled with the plain accent and an **ink** check (ink on straw 5.33:1), and the title in secondary text with a line through it. **Overdue:** the due line starts with the word "Overdue" or the day ("Yesterday") and is in Danger text (5.26:1 on milk); the word carries the meaning, not the colour. Rows are 62 high with a 1px sand divider.
- **Smart lists:** Today = due today plus everything overdue (overdue first); Scheduled = every reminder with a due date, grouped by day; All = everything.
- **Quick add** understands the same words as the Calendar: a title followed by `today`, `tomorrow`, `+3d`, a weekday name or `YYYY-MM-DD`, optionally `at 5pm`, `17:00`, and `every day|week|month|year` (or `every 2 weeks`). A **preview line** under the field shows how the sentence was understood (title, due, repeat, list) before Return adds it, so nothing is guessed silently; Esc clears. Return with no date adds an undated reminder to the current list.
- **Editing:** clicking a row expands it in place (no dialog): Title, Notes, Date, Time (optional), Repeat (Never, Daily, Weekly, Monthly, Yearly, every N), List, and an **Alert** switch (on by default when there is a time; an all-day reminder alerts at 09:00 like the Calendar). Return saves, Esc cancels. Space completes the selected row, Delete removes it, with an **Undo** toast for 5 seconds ("Reminder deleted   Undo"). Rows can be dragged to reorder within a list (a manual order, kept), otherwise sorted by due date.
- **Repeating reminders:** completing one marks it done and creates the next one (date advanced by the rule); only one open copy exists at a time, so the list never fills with future copies. A monthly reminder on the 31st lands on the last day of shorter months, like the Calendar.
- **Alerts:** at the due time the alarm daemon posts a notification (a toast with **Done**, **Snooze 10m** and **Open**), a card in the notification drawer, and the Calendar-alert sound (Focus mutes the sound and the toast but keeps the card). **Snooze** adds a one-shot alert and does not change the due date. The **Today** card shows how many reminders are due and how many are overdue (and the Today card's calendar highlight uses an ink numeral).
- **Data:** `~/Library/Reminders/<List>.rem`, plain text, tab-separated like the Calendar and Clock files (one `list` line: name, colour; then one line per reminder: id, done, due date, due time or "-", repeat and every N, alert, title, notes, order). Lines that do not parse are skipped and counted, never fatal; writes go to a sibling file and are renamed into place. Local time only. The app engineer defines the exact format.
- **Sandbox:** its own folder (`~/Library/Reminders`) only.
- **Needs:** the alarm daemon reads the new files (one more file kind, like the Calendar's), notification actions for Done and Snooze (window-system engineer; stubbed until then, the toast is informational), the Today card hook (window-system engineer).
