1 Activity Monitor: Processes: drawn 1:1 at 1024×768 and scaled to fit.

1. Activity Monitor: Processes

A table of what is running

medium

When

A process table like Activity Monitor or top: name, PID, state, CPU %, memory, threads, with a search box and a Quit button.

What you see

A Sandbox column shows which apps are confined, and the detail panel says in words what the selected app can read, whether it has network, and what it was refused today.

Detail

Anyone asking what is using the computer, and whether an app is behaving.

Build note

Reads /proc once a second. See SPEC-APPS.md.

Main elements

  • Tabs
  • Process table
  • Sandbox chip
  • Detail panel
  • Summary bar

Font note

Right-align numbers so the digits line up.

2 Activity Monitor: CPU: drawn 1:1 at 1024×768 and scaled to fit.

2. Activity Monitor: CPU

Per-core graphs

easy

When

Four live graphs, one per core, plus load.

What you see

Sixty seconds of history per core, load averages, the busiest processes, and interrupt rates.

Detail

Spotting a runaway process or a busy core.

Build note

From /proc/cpuload, /proc/loadavg and /proc/interrupts.

Main elements

  • Per-core charts
  • Load line
  • Busiest list
  • Interrupt rates

Font note

Charts are rectangles, one column per second.

3 Activity Monitor: Memory: drawn 1:1 at 1024×768 and scaled to fit.

3. Activity Monitor: Memory

Where the memory went

easy

When

A stacked bar of used and free memory, pressure, and the biggest users.

What you see

Page cache is shown separately (memory the system can give back) so a full-looking bar does not worry anyone.

Detail

Understanding memory without a lecture.

Build note

From /proc/meminfo and each process's VmRSS.

Main elements

  • Stacked bar
  • Pressure gauge
  • Biggest users

Font note

One headline sentence in 2x text.

4 Activity Monitor: Security: drawn 1:1 at 1024×768 and scaled to fit.

4. Activity Monitor: Security

Sandbox denials and audit events as sentences

medium

When

A timeline with filter chips, like an activity feed.

What you see

The audit log read as sentences (peek was refused /etc/passwd, You gave peek a file, moo2048 started sandboxed). A green line says the log is intact, from the tamper-evident chain.

Detail

Seeing what apps tried to do, and trusting the record.

Build note

Reads /proc/audit (permission being added) and runs the audit verify check. Read only.

Main elements

  • Intact banner
  • Filter chips
  • Event timeline
  • Raw record on click

Font note

Dots and the line carry the look.

5 Text Editor: drawn 1:1 at 1024×768 and scaled to fit.

5. Text Editor

Plain text with line numbers and light colour

medium

When

A plain editor: gutter, current-line highlight, status bar.

What you see

Light syntax colours that all pass 4.5:1 in both themes, soft wrap, undo that groups typing, and Versions from the filesystem for free.

Detail

Writing code and notes without an IDE.

Build note

Starts from scratch: line layout, wrapping and undo are new work for the app engineer.

Main elements

  • Gutter
  • Current line
  • Syntax colours
  • Status bar

Font note

Unifont at 8x16 with 18 px line height.

7 Text Editor: tabs and Markdown: drawn 1:1 at 1024×768 and scaled to fit.

7. Text Editor: tabs and Markdown

Many files, one window

medium

When

Tabs as in the Tabs spec; the dot on a tab means unsaved changes.

What you see

Markdown gets light styling (bold headings, a coloured bullet, a tinted code span) without rendering it. Autosave is off by default for files; Notes keeps its autosave.

Detail

Working on several files.

Build note

Uses the shared tab strip; Markdown styling is a line-based pass.

Main elements

  • Tab strip
  • Unsaved dot
  • Markdown styling
  • Soft wrap

Font note

Bold is the faux bold.

8 Calendar: Month: drawn 1:1 at 1024×768 and scaled to fit.

11 Clock: drawn 1:1 at 1024×768 and scaled to fit.

11. Clock

Local time, with optional world clocks

easy

When

An analog and a digital clock.

What you see

Local time only to start (the machine has a real-time clock but no time zone data). World clocks are optional and use a small table of fixed offsets, no daylight saving, and say so.

Detail

A clock you can read at a glance.

Build note

Wall clock via the RTC.

Main elements

  • Analog face
  • Digital time
  • World clocks (optional)

Font note

The time at 4x.

15 Preview: image: drawn 1:1 at 1024×768 and scaled to fit.

15. Preview: image

Open, zoom, pan

medium

When

A viewer with a toolbar, zoom steps and an info line.

What you see

Zoom is stepped (Fit, 25, 50, 100, 200%) so scaling stays simple. It opens only what you choose through the Open panel or drag, which makes it a good example of a sandboxed app.

Detail

Looking at pictures.

Build note

Needs the PNG/PPM/BMP decoders; scaling is done by the app (box or nearest).

Main elements

  • Toolbar
  • Zoom steps
  • Rotate
  • Info
  • Save as

Font note

Status line in secondary text.

17 Preview: unsupported files: drawn 1:1 at 1024×768 and scaled to fit.

17. Preview: unsupported files

Honest empty states

easy

When

A page that says it can not open the file, and why.

What you see

PDF: the page count and a text extract, but no page rendering yet. A JPEG before the decoder exists says so in plain words.

Detail

Main elements

  • Show text
  • Open in Editor

Font note

Two lines.

Notes for the engineers

SPEC-APPS.md lists, per app, what to build and what each needs (the app engineer and the window-system engineer). Everything is read from existing /proc files, the real-time clock and the monotonic clock. Not assumed: image decoders beyond the ones being written, time zone data, PDF rendering, vector fonts.
