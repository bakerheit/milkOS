1. Share: nearby devices

Files > Share opens the Milk Drop sheet

medium

When

Select a file in Files and press Share (or drag it onto a name under NEARBY in the sidebar).

What you see

A sheet lists the milkOS machines on the link: name, fingerprint and trust (Known, New device, KEY CHANGED). Machines that are not receiving are greyed with the reason. Send is a filled straw button.

Detail

Reads `drop list` (name, address, fingerprint, receiving, trust). Scan takes about 1.5 s, so show a small spinner in the sheet header.

Build note

A sheet with a list. Runs `MILK_TABLE=1 drop list` and re-runs it every few seconds while open.

Main elements

  • Share button in the toolbar
  • NEARBY sidebar group
  • Device rows
  • Trust chips
  • Send / Cancel

Font note

Fingerprints are 19 characters in Unifont, fine at 8 px per letter.

2 Sending: drawn 1:1 at 1024×768 and scaled to fit.

2. Sending

Progress and cancel

easy

When

The peer has accepted.

What you see

File chip, a straw progress bar and the numbers from the progress lines (40%, 416 KiB of 1024 KiB). Cancel stops the transfer.

Detail

Parses `drop: [####......] 40% 416 KiB / 1024 KiB`. Ends on `drop: sent ...` (exit 0) or `drop: ` (exit 1), which closes the sheet with a toast or an error row.

Build note

A progress bar bound to a parsed line. Cancel sends a signal (Ctrl-C equivalent).

Main elements

  • File chip
  • Progress bar
  • Status line
  • Cancel

Font note

Numbers in cocoa, one line.

3 Incoming, new device: drawn 1:1 at 1024×768 and scaled to fit.

3. Incoming, new device

A receive prompt in the Powerbox style

medium

When

Same look as the Open panel: it is milkOS's panel, not an app's.

What you see

Names who is sending what and how big, and for a new device shows the fingerprint large to compare with the sender's screen. The main button says what it does: Trust alice and accept.

Detail

Fed by `drop recv`: it prints `drop: wants to send you ()` then waits at `accept? [y/N]`. The sheet answers y or n on stdin. A known device shows a shorter version with Decline and Accept.

Build note

A modal panel owned by the window server (like the Powerbox) plus a pipe to `drop recv`.

Main elements

  • Sender and file
  • Big fingerprint
  • Trust warning panel
  • Decline / Trust and accept
  • Saved-to line

Font note

The fingerprint at 4x Unifont is the focal point.

4 Key changed: drawn 1:1 at 1024×768 and scaled to fit.

4. Key changed

The loud one

easy

When

A warning dialog with a red header.

What you see

Both fingerprints side by side (trusted before, now), plain advice (ask in person or by phone) and one destructive action, Forget bob and re-verify. Sending is blocked until then.

Detail

Triggered by the boxed `WARNING: bob's KEY HAS CHANGED` on stderr (exit 1) or by trust = KEY CHANGED in the table. `drop forget bob` is the action.

Build note

A dialog with two text blocks and a danger button.

Main elements

  • Red header
  • Two fingerprints
  • Advice line
  • Danger button

Font note

Danger red #B5473B with cream text is 5.26:1.

Main elements

Design notes

Everything here uses commands that already exist and keep their output stable. The one honest thing the design says out loud: files are checked but not yet encrypted. When encryption lands, that line becomes Encrypted and the sheet does not change.
